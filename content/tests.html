restFulQuacks

A browser-friendly test guide for the configurable C++ HTTP/1.1 server.

Before testing: run make re, then start ./webserv config/default.conf from the project root. The server listens on 127.0.0.1:8083.

Routing and redirects

1. Root route with curl

curl -i http://127.0.0.1:8083/
Expected now: HTTP/1.1 403 Error. autoindex on; is commented out, so the current router rejects the request becasue you cannot serve a directory with no index.

To test the configured redirect, uncomment return 301 https://www.instagram.com/chicken.quack.goose; in the root location, restart the server, and run:

curl -i --max-redirs 0 http://127.0.0.1:8083/
Expected: HTTP/1.1 301 Moved and a Location header pointing to Instagram.

Uploads and files

2. Upload directory listing

curl -i http://127.0.0.1:8083/uploads
Expected: HTTP/1.1 200 OK with an HTML autoindex of content/uploads.

3. Method restriction

curl -i -X PUT http://127.0.0.1:8083/uploads/test.txt
Expected: HTTP/1.1 405 Error. The uploads location permits only GET, POST, and DELETE.

4. Upload, read, and delete a file

printf 'upload test\n' > /tmp/webserv-upload.txt
curl -i -X POST --data-binary @/tmp/webserv-upload.txt \
    http://127.0.0.1:8083/uploads/test-upload.txt
curl -i http://127.0.0.1:8083/uploads/test-upload.txt
curl -i -X DELETE http://127.0.0.1:8083/uploads/test-upload.txt
curl -i http://127.0.0.1:8083/uploads/test-upload.txt
Expected results: POST returns 201 Created, GET returns 200 OK with upload test, DELETE returns 200 OK, and the final GET returns 404 Error.

Error handling

5. Missing resource

curl -i http://127.0.0.1:8083/secrets
Expected: HTTP/1.1 404 Error using content/error_pages/404.html.

6. Directory without autoindex

curl -i http://127.0.0.1:8083/secret
Expected: HTTP/1.1 403 Error, because the directory has no index and autoindex is disabled for the root.

CGI and query strings

7. GET CGI request

curl -i 'http://127.0.0.1:8083/cgi/hello.py?name=quack'
Expected: HTTP/1.1 200 OK. The HTML contains Method: GET and Query: name=quack.

8. POST CGI request

curl -i -X POST -H 'Content-Type: text/plain' \
    --data 'body from curl' \
    http://127.0.0.1:8083/cgi/post.py
Expected: HTTP/1.1 200 OK with Method: POST and Body: body from curl.

9. CGI request in Chrome

Open the CGI test URL. The page should show Method: GET and Query: browser=test.

Limits and raw HTTP

10. Large request body

The configured limit is 900 bytes. Send a 901-byte body:

head -c 901 /dev/zero | curl -i -X POST \
    -H "Content-Type: application/octet-stream" \
    --data-binary @- http://127.0.0.1:8083/cgi/post.py
Expected: HTTP/1.1 413 Payload Too Large. The request should be rejected before CGI execution or file creation.

11. Raw request with telnet

telnet 127.0.0.1 8083

GET /cgi/hello.py?client=telnet HTTP/1.1
Host: localhost
Connection: close
Expected: HTTP/1.1 200 OK followed by CGI output showing GET and client=telnet.
Cleanup: remove the local fixture with rm -f /tmp/webserv-upload.txt. The upload test deletes its server-side file at the end.
